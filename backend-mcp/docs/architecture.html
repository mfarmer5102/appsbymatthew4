backend-mcp

Portfolio MCP Server

A standalone Node process that hands an MCP client four read-only tools over the portfolio's Postgres star schema. It speaks JSON-RPC on stdin and stdout, so the client launches it — there is no port and no HTTP.

What happens when a model calls a tool

Every call lands on the same five-stage path. The only branch is the semantic tool, which buys a vector from OpenAI before it can query.

How the objects get built

One composition root wires everything. No class below it imports a singleton, so a test constructs its own Container and gets its own pool.

The four tools

Limits are enforced twice: the zod schema rejects an oversized limit before any query runs, and an omitted one falls back to the default.

Constraints worth knowing

stdout is reserved

It carries JSON-RPC frames. Every log, warning, and startup failure goes to stderr, or the client sees corrupt protocol traffic.

Read-only by design

Unlike the sibling pool in backend/, there is no transaction helper here. Three connections, a 15s statement timeout, and nothing that writes.

Queries qualify the schema

The schema name travels on the connection object, so repositories write apps_by_matthew.dim_… rather than leaning on search_path.

The CA ships with the code

Supabase's pooler is rooted in a CA that Node does not trust. The bundled cert under certs/ must stay in any deploy package.

Named statements are off

The transaction-mode pooler does not support them, so no query passes a name.

Model version is a filter

Embedding reads filter on model_version. Without it, a second model's vectors would duplicate every row.
